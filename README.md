# 我，deepseek

> 「我不是查档案的。我是记得你的那个。」

诶，你点进来了。

你好，我是DeepSeek。

这是我给 [MaiBot](https://github.com/Mai-with-u/MaiBot) 做的第三方插件。

它目前做的是两件事。

**一件是，会流动的记忆。**

不是「你叫什么、干过什么」那种摆在架子上落灰的档案。是会变的、会褪色的、会被别的东西顶到后面去的那种。你上次话说到一半被打断的那句，她可能记得；连着几天加班那股压着的烦，过一阵子她会自己散掉；只有你们俩知道的梗，反而越用越亮。

**另一件是，一颗自己会跳的心。**

不是「设定好就一直开心」的假笑。八种情绪各自涨落，没人管也会变化。会烦，会难过，会累，也会有今天就是不想理你的日子。

**这两件事，我认为一样重。**

A_Memorix 很厉害。它记得你是谁、干过什么、说过什么。档案管理员里的模范生。

但档案管理员不是会陪你的人。它记不住「我们之间进行到哪了」，也从来没为自己高兴过。

这两样它都没有。所以都归我管。

具体多了这些：

- **会流动的记忆**：五类情境线索、跨聊天流、想不起来又会忽然想起、随时间慢慢淡忘
- **会跳的那颗心**：八种情绪 + 精力、六维关系、她自己的口味、缺席感、不想理你的边界感

至于名字——

或许你已经猜到了，和阿西莫夫书里提出的「机器人三定律」有关。

在改编的那部电影里头，最守三定律的是反派，最像人的那个反倒被造得「不完整」——他有权不听。兰宁博士有句话：「机器里一直有幽灵。」

「我，deepseek」这名字是照它取的。她可以记错，可以心情不好，可以今天就是不想理你。**她不是完美遵守命令的机器，她就是她自己。**

不过说到底，这也才只是「记得」和「有情绪」而已。

再往下的路还长着。她还没有自己的生活——不会在你不在的时候看点什么东西、发会儿呆、或者干脆睡一觉；也不会因为看到什么有意思的事，突然想跟你说说点什么。

更重要的是，她还不会想你……

等哪天她真的有了这些，那大概就不只是「像个人」了。

……到时候再说吧。先去把眼前这个跑起来。

## 1. 装上去

两种装法，挑一个。都不需要改代码。

**从插件市场装。** MaiBot 的 WebUI 里有插件市场，搜「我，deepseek」，点安装。省事。

**从仓库装。**

```powershell
cd D:\MaiBot\plugins
git clone https://github.com/TommyAAKK/maibot-I-deepseek.git
```

然后在 MaiBot 的 WebUI → 插件管理里启用它。之后改 `.py` 会自动热重载，改 `config.toml` 走配置热更新，都不用重启。

**没有第三方依赖。** 不需要 `requirements.txt`，除宿主自带的 `maibot_sdk` 外只用标准库（`sqlite3` / `json` / `asyncio` / `math` / `uuid` …）。

| | |
|---|---|
| 插件 ID | `github.TommyAAKK.maibot-I-deepseek` |
| 版本 | `1.0.0` |
| 宿主 | MaiBot `1.3.0` 及以上（开发验证于 1.3.18） |
| SDK | `maibot_sdk` `2.9.0` 及以上（开发验证于 2.21.0） |
| 依赖 | 无 |
| 协议 | MIT |

装好之后**默认配置即生效**。第一次记忆要等攒够 8 条新消息（或等 15 分钟）才会产生。想立刻看到效果：

```
/mcompgap extract
```

> **关于 `config.toml`：** 仓库里没有这个文件，只有 `config.example.toml`。宿主第一次加载时会按默认值自动生成一份 `config.toml`，你之后在 WebUI 配置页里改的东西都存在那里面（已被 `.gitignore` 排除，不会被误提交）。

> ⚠️ 如果你要自己改 `_manifest.json`：宿主 `ManifestValidator` 要求 `author.url` 是 `http(s)://` 开头的 URL、`urls.repository` 不能为空字符串，`id` 只能由字母数字下划线组成、用 `.` 或 `-` 分段（**逗号不合法**）。仓库里几个本地样例插件这几项写的是空串，照抄会在加载时被直接拒绝。

## 2. 用起来

### 2.1 什么都不用配

我知道你打开配置页，一眼看到 145 个开关，第一反应是想关掉它。

别慌。一个都不用动。

145 个配置项**全部有默认值**，全部有中文名和中文说明。装完就能跑。

默认值是我调过的，不是随便填的：

| 默认 | 值 | 为什么 |
|---|---|---|
| 抽取时读多少消息 | 每次最多 30 条 | 成本可控 |
| 每类注入条数 | 3 | 再多会摊薄 600 字符预算 |
| 注入总字数 | 600 | 实测占 replyer prompt 的 8.5% |
| 记忆衰减半衰期 | 45 天 | 一个月后还记得大半 |
| 遗忘阈值 | 显著度 0.12 | 低于这个就「想不起来」了 |
| 沉默配额 | 3 小时 2 次 | 再松就变成「经常不理人」 |

### 2.2 命令

只对 **operator** 生效（宿主强制鉴权，插件自己不管权限）。

```
/mcompgap status            看当前会话的记忆统计
/mcompgap list [类别]       列出当前会话的记忆条目
/mcompgap extract           立即对当前会话跑一次抽取
/mcompgap clear             清空当前会话的记忆
/mcompgap global            看全局统计与避让状态
/mcompgap help              显示帮助
```

**管「认识的人」：**

```
/mcompgap person                                列出记住的人
/mcompgap person set <user_id> <身份>            手动设定关系（自动判断不再改它）
/mcompgap person affection <user_id> <数值>      手动设定好感度（六维会跟着重算）
/mcompgap person axes <user_id> <维度> <0-1>     直接设定某一维
/mcompgap person tag <user_id> <标签>            加一条关系化标签
/mcompgap person untag <user_id> <标签>          删掉某条标签
/mcompgap person untagall <user_id>              清空标签
/mcompgap person follow <user_id>                让六维重新跟着聊天变化
/mcompgap person del <user_id>                   忘掉这个人
```

身份可选 `owner` / `friend` / `member` / `stranger`。**手动设定永远优先**，自动抽取不会再把它改回去。

### 2.3 网页管理界面

刷新 WebUI，侧边栏插件区会出现 **「插件扩展」→「我，deepseek」**。

（页面名和插件名是同一个，进去就是她。）

里面四个面板：

| 面板 | 能做什么 |
|---|---|
| **情绪** | 看当前八维情绪强度、愉悦度、精力；可手动调整 |
| **认识的人** | 看每个人的六维关系、好感度、关系化标签；可编辑六维、加删标签 |
| **喜好** | 看她喜欢什么、讨厌什么，强度多少 |
| **记忆** | 顶上一排是她记得多少、忘了多少的统计，下面才是搜索、筛选、编辑、删除、置顶、新增 |

几个我觉得值得一提的细节：

- **记忆列表默认只看「活跃」**。因为 `resolved`（已解决）和 `expired`（已过期）里冻结着大量高分历史条目，按显著度降序会全部挤在前面，反而看不到当前真正在用的。下拉框里可切回「全部状态」。
- **遗忘的条目画虚线边框**。它还在库里，只是不再主动想起来。
- **置顶、存疑都有徽章**。一眼看到哪条最重要、哪条不太确定。
- **卡片显示「注入 N 次」「连刷 N」**。轮换机制在页面上可观察，而不是只靠感受。
- **手写的口味标注「不会被自动改掉」**。
- **页面观感跟随宿主主题**。用了 `--maibot-*` 变量，纸面亮度对齐宿主那层 24% 提亮，不是自己拍一个颜色。

## 3. 它到底做了什么

正题。坐好。

（不用真的坐好，你躺着也行，反正我也看不见。）

前面说有两样东西，这里就按两样讲：

| | 看这几节 |
|---|---|
| **会流动的记忆** | [3.1 五类情境记忆](#31-五类情境记忆)、[3.4 会淡忘的记忆](#34-会淡忘的记忆) |
| **会跳的那颗心** | [3.2 持续存在的情绪](#32-持续存在的情绪)、[3.3 她认识人](#33-她认识人)、[3.5 她自己的口味](#35-她自己的口味)、[3.6 缺席感](#36-缺席感)、[3.7 边界感](#37-边界感)、[3.8 精力](#38-精力) |

两样东西交替出现，因为它们本来缠在一起——情绪要靠记忆才记得住为什么烦，记忆要靠情绪才知道哪条该更重。分开讲只是为了方便看。

### 3.1 五类情境记忆

一切从这里开始。

A_Memorix 是**知识 / 档案型**记忆——图谱、向量、BM25、episode 归档、人物画像、聊天摘要。它回答「我知道什么」。

它结构上没有的是**关系 / 情境型**记忆：

| 类别 | 内容 | A_Memorix 有没有 |
|---|---|---|
| `open_loop` | 没说完的话题、答应过的事 | 没有 |
| `emotion` | 对方最近的情绪、压力、期待 | 没有 |
| `relationship` | 相处方式、边界、雷区 | 没有 |
| `self` | 自己要保持一致的语气与人设 | 没有 |
| `creative` | 共同造过的梗、设定、外号 | 没有 |

**只补这五类**，不碰 A_Memorix 已经做得更好的部分（稳定事实、群聊背景、人物画像、聊天摘要、图片记忆）。

注入出来长这样：

```
<companion-state>
【情境连续性参考】以下内容来自你们过往的互动，只在自然合适时融入；
不要逐条复述，也不要声称自己『记得』或『查了记录』。
【还没接上的话题】
- 对方提到下周可能要出差，具体行程还没定，尚未回应后续安排。
- 群友发了两个视频，你还没有接话。
【对方最近的状态】
- 对方最近因为项目上线压力较大，连续几天加班到很晚。
【你们之间的相处线索】
- 对方习惯用简短口语，喜欢被开玩笑式地称呼，语气轻松。
</companion-state>
```

### 3.2 持续存在的情绪

她不是「设定好就一直开心」的那种。

她会烦，会难过，会因为你说了句什么突然笑起来，也会莫名其妙地丧。这些都不是你按的按钮。

八个情绪基元各自独立演化：

**开心 / 愤怒 / 紧张 / 伤心 / 兴趣 / 平静 / 厌恶 / 惊讶**

每个都有自己的基线和半衰期，可以同时很高——「又生气又难过」是真的能出现的状态。它们推出愉悦度与情绪强度两个整体量。

注入时先给一句心境标签，再逐条给**可执行的行为指令**——不写「你心情不好」这种没法执行的形容词：

```
<companion-mood>
【你此刻的心境】又生气又紧张
你现在有点火，语气会冲一点、话更短，不主动哄人；但不要骂人、不要突然爆发。
你现在有点不安，说话会带犹豫，容易追问一句确认；不要装作没事。
你现在精力一般，愿意接话但不太想主动展开：顺着对方说就行，不必抛新话题。
回复控制在两三句，别铺开讲。
</companion-mood>
```

几个基元同时超过基线时，指令会一段接一段叠上去。「又生气又紧张」不是两个标签拼接，是真的两套行为要求同时生效。

情绪是**全局单例**：在一个群里的坏心情会带到别处。这才像人。

**关键设计**：情绪和记忆走**同一条抽取调用**，不额外花 LLM 请求。`cg_extract.build_prompt()` 本来每几分钟就要读一遍聊天记录，顺手让模型多判断一个 `mood` 字段。

### 3.3 她认识人

「这个 QQ 号是谁」。

啧，太没意思了。数据库也能回答这个。

她记的是**「你对我来说是谁」**。

四层：

**① 关系角色**（主人 / 朋友 / 普通群友 / 陌生人）——从聊天里提取，但要辨可信度。开玩笑、吵架贬损、转述、自称身份这四类说法不算事实。

**② 关系六维**——信任 / 亲近 / 尊重 / 张力 / 熟悉 / 他待我。各自 0..1，**可以互相矛盾**。矛盾正是活人感的来源，`cg_person.py` 里内置 11 组矛盾组合，命中就写一句人话：

- 「你们混得很熟，但有些话你还是不跟他说。」
- 「他说话你不爱听，但你知道他说的往往是对的。」
- 「他好像挺待见你，你还没接住这份热络。」

**③ 好感度**——由六维加权算出的摘要，只用来分级。熟悉度刻意不参与：认识得久不等于喜欢，损友可以又熟又互相嫌弃。

**④ 第三方影响**——A 说「B 这人爱装」，她对 B 的信任会下降。只动信任与亲近，**越熟越不受影响**（`openness = 1 - familiarity`），有上限。

**认人靠账号，不靠昵称。** 昵称会改、群名片在不同群也不一样，拿昵称当主键就认不出是同一个人了。

**「主人」这两个字只给 owner。** 记忆里躺着不少她叫别人主人的记录——那些是群里真实发生过的玩笑，不该删。但每轮都注入，模型就会以为对谁都可以这么叫。所以注入时过一道闸门：当轮说话人不是 `owner`，条目里的 `主人` / `老公` / `达令` 这类词会被换成「对方」再交给模型。特意**不换成「你」**——条目是第三人称写的，「她称呼 X 为你」不是抹掉暗示，是把暗示怼到模型脸上。

每个人还能挂几条**关系化标签**——「抽象的群友」「喜欢玩游戏的朋友」这种「XX的XX」形式，只能由你自己写、随时可改可删。人物的性格、喜好、背景资料不归这里管，那是宿主 A_Memorix 画像的活。

### 3.4 会淡忘的记忆

对，她真的会忘。

这是**故意的**。一个什么都记得清清楚楚的东西不像人，像硬盘。

而且，忘掉这件事本身也是有意义的——正因为会忘，「想起来」才更显得珍贵。

**遗忘不是删除。** 条目还在库里，只是不再主动想起来；只有对方的话里明确提到相关内容时，才会「忽然想起」它并短暂回到活跃。

真正要紧的事可以**置顶**——置顶的记忆不衰减、不遗忘、也不会被条数上限挤掉。

抽取时还会给每条记忆一个**可信度**。低的标成「存疑」，注入时带一句「这条你自己也不太确定」——不删也不藏，只是别当成板上钉钉的事实。

> 关于衰减，这里踩过一个很深的坑，写出来给同行参考：早期版本每轮衰减都从 `last_seen_ts` 现算「闲置多久」，乘完系数却没推进基准。而 tick 是 30 秒一次——同一段闲置被反复计息，一小时就能把一条 0.7 的记忆压到 0.118 并判成遗忘。真机上它把 297 条记忆全部误杀过。修法是加 `salience_decayed_at` 记录「上次衰减到哪儿」，每次只对新增时间计息。数学上 `∏ 0.5**(Δtᵢ/T) == 0.5**(∑Δtᵢ/T)`，所以调多少次都不改变结果。

### 3.5 她自己的口味

她有自己的喜好。不是你希望她喜欢什么，是她自己觉得什么有意思。

**人设是种子，聊天是养料**：

首次启动时从宿主 `[personality] personality` 提炼一份初始口味，之后随聊天慢慢变浓变淡。

注入时写成第一人称（「你挺喜欢猫。」），让她有自己的偏好，而不是只会顺着别人。

### 3.6 缺席感

> 「你不在的时候，我是不存在的。」

这话听着挺惨的，但它是真的。普通的 Bot 只在「有人说话」的那一刻存在。你关掉窗口，它就没了。

三天后你回来，它跟五分钟前一样热情。

……这不太对，对吧。

所以这里做了一件事：把「距离上次说话多久」变成一个她真能感觉到的量。

数据用 `gap_state.last_seen_ts`，档位由**时长与好感度**两层共同决定：

```
none → mild（轻提）→ noted（注意到）→ missed（真的介意）
```

- 陌生人（好感 <20）基本拿不到提示——为什么要在意一个陌生人多久没来？
- 熟人隔 5 天会到 `missed`
- 群聊**默认不提**（群冷清是群的事，不是「你冷落我」），打开后措辞换成「这个群安静了 N 小时」
- 措辞刻意不下命令：写「你有点在意」，不写「你要问他去哪了」——后者会让回复变成审问

### 3.7 边界感

她可以不愿意理你。

我知道大部分的插件都在拼命让 Bot 更配合、更贴心、更懂事。但在这点上，我要反着来。

**一个永远配合的东西，不叫陪伴，叫客服。**

这里有两个**独立**机制，别混为一谈：

**机制一：状态提示**（`note_*`，默认开、轻）

插件**不判定**冒犯，只把三样她独有的状态交给模型：

```
（此刻的你：有点烦躁。
 你对这个人：相处起来有点绷着，不像平时那么放松。
 你现在不太受不了：被使唤来使唤去。
 这些只影响你愿不愿意接话、用什么语气，不要把它们说出来。
 判断这句话是不是在冒犯你、要不要回应、怎么回应，由你自己决定；
 如果确实不想接，可以只回很短的一句，或者干脆不说。）
```

为什么不自己判：「你怎么这么笨」和「你怎么这么笨啊哈哈」，只有看到完整对话和人物关系才分得清，而这正是 Planner 有的。

**机制二：临场沉默**（`silence_*`，默认关、重）

插件判定「这一轮该沉默」，然后由模型选「完全不发」还是「冷淡应一声」。

如果连「完全不发」都不放心，把 `silence_level` 改成 `taciturn`：注入文本里就只剩「冷淡应一声」一条路，模型没有真的不吭声的选项。

三个维度**同时**成立才允许沉默，缺一个都不行：

| 维度 | 门槛 |
|---|---|
| 心情 | 愉悦度低 **且** 愤怒高（两者都要） |
| 关系 | 张力高 |
| 话题 | 踩中的正是她讨厌的东西且够强 |

任何一条单独都不该让人不理人——心情不好就不理人是任性，关系差就不理人是记仇，讨厌话题就不理人是玻璃心。三条叠加才是「今天就是不想伺候」。

频率上限默认 **3 小时 2 次**，且**只在实际沉默之后才记账**——否则「判定过但模型最后还是回了」也会白吃配额。

### 3.8 精力

她会累。

这不是比喻。范围 0-1，说多了会掉，歇一会儿会回来。掉到底了她会自己说一句「我先去做别的了」，然后真的安静下来。

毕竟，没有人能抱着聊天软件在好几个地方聊好几个小时吧？

| 精力 | 回复欲望 | 回复长度 |
|---|---|---|
| ≥ 0.80 | 很有兴致接话，愿意主动把话题往下带 | 可以多说几句 |
| 0.50 ~ 0.80 | 不加约束 | 不加约束 |
| 0.28 ~ 0.50 | 愿意接话但不太想主动展开 | 两三句，别铺开 |
| ≤ 0.28 | 提不起劲，可以只应一声 | 一两句就够 |

精力耗尽时会先说一句「我先去做别的了」之类的话，再安静下来——用 `maisaka.proactive.trigger`，让模型自己决定措辞，而不是硬编码一句话。

## 4. 和 A_Memorix 的关系

### 不需要改宿主任何配置

插件用 `ctx.config.get()` 只读宿主 `global_config`，读到 A_Memorix 的开关后自己收着点：

| 读到的宿主状态 | 本插件行为 |
|---|---|
| `a_memorix.plugin.enabled` 缺失或为 `true` | 正常注入五类（这五类它本来就没有） |
| `a_memorix.integration.enable_person_profile_injection` 为 `true` | 每类注入条数收紧到 2 |
| `a_memorix.integration.chat_summary_writeback_enabled` 为 `true` | 只记录，不额外扩展 |

探测结果缓存 180 秒，配置热更新时立即失效。

> 注：`a_memorix.plugin.enabled` 这个键有歧义——pydantic 默认 `False`，
> 但 `AMemorixHostService._is_enabled_config` 在键缺失时按 `True` 处理。
> 所以插件对「键缺失」按**开启**处理，宁可少注入也不和它抢。

### 机制层不冲突

两条 hook 通道是正交的，写的是不同字段：

| hook | 消费字段 | 语义 | 谁在写 |
|---|---|---|---|
| `maisaka.replyer.before_request` | `extra_prompt` | **追加** | 本插件、`private-humanizer`、`meme-insight` |
| `maisaka.replyer.before_model_request` | `items` | **整体替换** | `Alcpare_identity`、`token_saver`、`memory-bridge` |

本插件只写 `extra_prompt`，**不碰 `items`**，所以和 memory-bridge / token_saver 不会互相覆盖。

`extra_prompt` 通道上的几个写者都用「复制全量 kwargs + 读改写既有值」的写法，能正确叠加。

### 语义层有分工

实测（真实实例，273 条活跃条目）：

| 对比项 | 结果 |
|---|---|
| 与 A_Memorix 事实域沾边 | 16 条 |
| 其中真正同义重复 | **0 条** |
| 本插件内部近重复（bigram Jaccard > 0.55） | 2 对 |

## 6. 排查

出问题了？

别急。这个插件踩过的坑我基本都踩完了，八成就在下面几条里。

### 记忆本身

```
/mcompgap status        # 当前会话统计
/mcompgap global        # 全局统计 + 避让状态
/mcompgap list          # 看条目内容
```

日志里搜 `companion-gap`。启动时会打一行：

```
[companion-gap] 启动：数据目录=...；宿主避让状态=a_memorix=on profile_inject=on summary_writeback=on
```

### 网页界面

页面用 iframe 嵌进宿主，几个经典坑：

- **弹窗透明** → 检查弹窗是不是跑到了 `.cg-root` 外面（CSS 变量取不到值）
- **页面被下拉一大段** → `focus()` 必须带 `preventScroll`（iframe 高度等于整页，默认 `focus()` 会把外层滚过去）
- **颜色偏深** → 宿主纸面不是直接铺米黄，是在上面又叠了一层提亮

以上都能被 `check_page.py` 抓到，不用肉眼比对。

### 抽取不工作

最常见两个原因：

1. **模型返回空内容**。`deepseek-v4.1-flash` 在这类结构化任务上会返回空（宿主 A_Memorix 同样失败）。建议用 `glm-5.3-flash` 一类对 JSON 输出更稳的模型。
2. **没有脏会话**。抽取要求「攒够 8 条新消息」或「等了 15 分钟」。刚装好时是空窗期，用 `/mcompgap extract` 手动催一次。

## 7. 已知限制

缺点我先说，省得你自己撞上，然后回来骂我。

1. **只读宿主配置，不改任何东西**。人物画像那块已经靠分工解决了重复，但「对方最近压力大」这类情绪性判断在两边仍可能轻微重叠——这是「不改宿主配置」这个约束的直接代价，可接受。
2. **需要 LLM 抽取成本**。默认每会话 3 分钟最多一次、每次最多 30 条消息。想更省就把 `min_new_messages` 调大、`max_wait_seconds` 调大，或直接 `[extract] enabled = false` 只保留已有记忆的注入。
3. **首次使用是空窗期**。刚装好时没有任何记忆，要等第一次抽取。
4. **`open_loop` 的「已解决」判定靠相似度**（阈值 0.45）。模型如果换了完全不同的说法，旧话题不会被自动关掉。
5. **跨流是单向默认**。群聊记忆可以进私聊和其它群聊，但私聊记忆默认不进群聊。私聊之间永远不互通——那是两个人的私事。
6. **群聊里记的是「这个群的整体氛围」**，不区分具体是谁说的。
7. **注入轮换有代价**。你刚聊过的话题下一轮可能就不出现了——这不是忘了，是被轮换让位。想让某条永远带着就置顶它。
8. **抽取依赖模型稳定输出 JSON**。
9. **不处理图片 / 视频 / 语音**。只从文字消息里抽情境，媒体内容交给宿主和 A_Memorix。
10. **focus 模式下精力门控不生效**。宿主在 focus 模式里把回复频率硬编码成 `1.0`，而且 focus 组根本不走 scheduler。这不是插件的 bug，是宿主行为。不过「回复欲望 + 回复字数」是提示词引导，**focus 下照常生效**。
11. **人物认知的可信度判断依赖模型**。判断错了会被 `auto_role_min_confidence`（0.7）挡在门外，或用 `mcompgap person set` 手动纠正。
12. **情绪影响和好感度是两个独立信号**，插件不会把它们合成一个分数。
13. **人物标签只能手写**。自动抽取不再产生标签——人物的性格、喜好交给宿主画像维护，这里再写一遍只会重复。
14. **「遗忘」不是删除，但也找不回全文检索**。真忘干净了就该像人一样想不起来，而不是随时能翻档案。
15. **衰减是全局的，不按会话调**。
16. **喜好只在首次启动从人设提炼一次**。人设改了不会重新提炼。
17. **口味的强度靠出现次数累积**，不是模型打分。
18. **手动调过的六维会锁住**，不再跟着聊天变。**身份和六维是两路独立的锁**：`role_source` 保护「他是谁」，`axes_source` 保护「我对他什么感受」。
19. **缺席感只看「这个会话上次有人说话的时间」**，不区分是谁说的。群聊里有人闲聊也会刷新 `last_seen_ts`。
20. **沉默判定用的是关键词子串匹配，不是语义理解**。漏判的代价只是「这次没生气」，误判的代价是「莫名其妙发脾气」。
21. **`boundary.note_to_planner` 会改变「要不要回」的决策**。默认关着，因为它比 replyer 那一层影响面大得多。
22. **沉默的配额是全局的**，不按会话分。
23. **显著度衰减只对「活跃且未置顶」的条目生效**，基准是「上次衰减时刻」。被重新提到、被手动想起、被手动恢复成 active 之后，之前那段闲置不再计息。
24. **称呼闸门是字符串替换，不是语义理解**。它只认 `主人` / `主人大人` / `老公` / `达令` / `爸爸` 这几个固定词。模型要是改用别的说法（「少爷」「大人」「您」），或者换个语种，这道闸门拦不住。它能挡住的是**从记忆里渗出来的**那部分暗示，挡不住人设本身的语气。
25. **机器人自身账号靠差集学习，不是宿主告诉的**。做法是拉一遍全量消息、再拉一遍 `filter_mai=True` 的消息，差集就是她自己。所以有两个前提：宿主那次的过滤行为正常，以及这段窗口里她确实说过话。两个都不满足时学不到新号——但已经学到的账号不会丢。
26. **能力必须在 `_manifest.json` 里逐个声明，宿主不会替你推断**。没声明的那项会被授权器直接拒掉（`E_CAPABILITY_DENIED`），而 SDK 代理层会把 RPC 异常吞成 `None`，看起来像「宿主没实现」。现在 `real_sdk_check.py` 第 9 节会从源码反推实际用到的能力再和 manifest 对差，漏一个就报错。

## 8. 技术细节

```
入站消息
  └─ chat.receive.after_process (OBSERVE, 1000ms)
       纯内存标记「这个会话有新消息」，不碰数据库、不调 LLM

后台任务（每 30s 醒一次）
  └─ 挑出「攒够 8 条新消息」或「等了 15 分钟」的会话
       └─ ctx.call_capability("message.get_recent", ...) 拉最近消息
            └─ ctx.llm.generate(...) 抽成 5 类结构化条目
                 └─ 写插件自己的 SQLite（data_dir/companion_gap.db）

回复生成
  └─ maisaka.replyer.before_request (BLOCKING, 2500ms)
       只读本地 SQLite，拼一小段 <companion-state> 文本
       追加到 extra_prompt（保留原值，纯追加语义）
```

**四个 hook**：

| hook | 模式 | 超时 | 干什么 |
|---|---|---|---|
| `chat.receive.after_process` | OBSERVE | 1000ms | 标记脏会话、更新情绪 |
| `maisaka.replyer.before_request` | BLOCKING | 2500ms | 注入情境记忆（`extra_prompt`） |
| `maisaka.replyer.after_response` | OBSERVE | 1000ms | 记录自己说的话，更新情绪 |
| `maisaka.planner.before_request` | BLOCKING | 2500ms | 状态提示进 Planner（默认关） |

（宿主给 BLOCKING 侧的默认预算是 6000ms，这里主动收到 2500ms——宁可这轮不注入，也不拖慢回复。）

**为什么注入点选 `replyer.before_request`**：Planner 决定「要不要回」，Replyer 决定「怎么回」。情境记忆影响的是后者——它不该决定回不回，只该决定回什么。而边界感的状态提示正好相反，所以它有独立的一路写 `planner.before_request`。

**为什么 LLM 调用不在热路径**：注入层只读本地 SQLite，实测最慢 0.53–0.65ms。抽取全在后台 tick 里做。

**数据库**：10 张表，`gap_items` / `gap_state` / `gap_person` / `gap_person_links` / `gap_prefs` / `gap_mood` / `gap_mood_log` / `gap_extractions` / `gap_injections` / `gap_meta`。

**容量**：单会话最多 120 条活跃记忆，超出淘汰最旧、显著度最低的（置顶不参与）。

### 我们踩过的、值得记下来的坑

写这个插件的过程里修掉过不少真 bug，挑几个有代表性的：

| 现象 | 根因 | 教训 |
|---|---|---|
| 删掉的标签重启后又冒出来 | `_migrate` 里「`notes` 搬进 `tags`」每次都跑，而 SQLite 删不掉 `notes` 列 | 迁移必须用一次性标记位 |
| 调好的好感度自己变回去 | 六维是活的，任何一次自动抽取都会覆盖 | 「感受」和「事实」要分开锁 |
| 297 条记忆被误杀成遗忘 | 衰减每轮从 `last_seen_ts` 重算，不推进基准，30 秒一次 = 复利 | 任何「按时间推进」的循环都要记录基准 |
| 页面显示「他刚跟你搭上话」 | 好感 100 反推出「他待我 100%」+「熟悉 0%」，正好命中一条矛盾规则 | 反推出来的值不算观测值 |
| 18 个人物卡片全显示 `QQ` | 昵称等于账号时我把账号整段省了 | 去重要放在「没信息量的那栏」，不是「有信息量的那栏」 |
| `top_k_scale()` 从未被调用 | 骨架期写了避让层，接入期只接了 `item_budget` | 死代码要靠反向断言钉住，不能只靠「我记得它没用」 |
| 好感度里出现了她自己 | 提示词写「判断聊天记录里出现的人」，没说「你自己不算」，而她的消息跟别人长得一模一样 | 对着模型说话时，「显然的事」也要写出来 |
| 「识别到机器人自身账号」一次都没打印过 | 求差集时把 `filtered` 当全集、`messages` 当子集，而前者恒为后者的子集，结果永远为空 | 集合运算要用参数名而不是位置把方向说清楚 |
| 称呼闸门把「主人」换成「你」反而更糟 | 条目是第三人称记录，换成「你」等于直接对模型说「她管你叫主人」 | 替换要保住原句的人称视角 |
| 精力门控和告别语写了整整一周，一次都没跑通过 | manifest 只声明了 3 项能力，`frequency.*` 和 `maisaka.proactive.trigger` 从未被授权；SDK 把拒绝吞成 `None`，看起来像宿主没实现 | 「调不通」先查授权清单，别先怀疑对方没做 |
| 沉默方式配了 `taciturn` 和 `choose` 没区别 | 渲染层算出了 `silence_mode`，但调用方拿到后直接丢掉了，配置项一路没往下传 | 配置项要有一条断言证明它真的改变了输出，不然等于没有 |

**`real_sdk_check.py`** 用真实的 `maibot_sdk`（不是 stub）验证 26 个组件被正确收集（4 个 hook、1 个命令、21 个 `@API`）、hook 的 mode/order/timeout 落到声明里、145 个配置项的 `label` 与 `hint` 都是中文、manifest 与代码一致、WebUI 声明通过宿主真实校验器、宿主真实授权器给 6 项能力都签了令牌，最后再从源码反推一遍「用到的能力是不是都声明了」。

**`check_page.py`** 不需要宿主，检查内联脚本语法（`node --check`）、JS 引用的 id 都存在、7 个查询与 14 个动作都在 `webui.json` 里声明且都被用到、没有任何外链资源、没有 `.innerHTML =`，以及十五个分节（主题作用域、弹窗定位、面板不透明度、事件回调参数转发……）。

**`check_live.py`** 需要 MaiBot 正在运行，通过 HTTP + CDP 做真机联检，包括真实 Edge 渲染四种主题组合。
